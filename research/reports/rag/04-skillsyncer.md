# 04. SkillSyncer：脱敏、经历级向量与两阶段候选比较

## 项目卡片

- GitHub：[Mightype/Multi-Agent-Resume-Screening](https://github.com/Mightype/Multi-Agent-Resume-Screening)
- 本地源码：`research/source-code/rag/04-skillsyncer`
- 锁定版本：`9e80ae137db6`
- 技术定位：多 Agent 简历筛选、个人信息脱敏、经历级匹配与候选比较。
- 一句话判断：该项目最好的一点是将候选人的“人生经历”作为匹配单元，并把高召回向量筛选和高成本 LLM 比较分开。
- 重要性：P0/P1，兼顾隐私与推荐质量。

## STAR 分析

### S — Situation

整份简历存在大量与岗位无关的文本，姓名、联系方式、照片等信息还会引入隐私与偏差。真正能证明岗位适配性的往往是少数工作或项目经历；若只比较整份简历，强经历容易被其他内容稀释。

### T — Task

先屏蔽非必要个人信息，把简历压缩为有限、语义完整的经历单元，通过低成本向量检索筛出候选，再用 LLM 对完整证据做更细的比较和排序。

### A — Action

项目首先遮蔽 PII，再由 LLM 把每份简历拆成不超过约 10 个 life events。每段经历独立嵌入，与岗位描述计算相似度。候选级向量分不是简单平均，而是突出最相关两段经历：`(2*s1 + s2)/3`，让最强证据权重更高。向量阶段得到 top-5 后，再读取完整简历，由 LLM 做成对比较或综合推理，形成最终排序。

### R — Result

经历级索引更容易解释“为什么推荐”，脱敏降低无关属性干扰，两阶段架构也节省 LLM 成本。风险在于 LLM 切分结果不稳定、只看 top-2 会忽略持续性和负面约束、成对比较的成本随候选数平方增长，并且“脱敏”不能替代合法处理依据。

## 完整执行流程

1. 接收简历并建立不可变原件，记录授权和保留期限。
2. 检测姓名、电话、邮箱、地址、照片等 PII，生成面向模型的脱敏副本。
3. LLM 将副本分解为最多约 10 个完整经历事件。
4. 每个事件保存类型、组织、职责、技能、日期和原文证据。
5. 为经历生成向量；岗位描述也生成向量。
6. 计算每位候选人所有经历与岗位的相似度，取最高两段加权聚合。
7. 根据聚合分筛到 top-5，并保留命中经历。
8. LLM 读取岗位、候选人结构化信息和命中证据，执行成对或列表式比较。
9. 输出排序、优势、缺口和证据；敏感原件只对授权人员展示。

## 难点与重要性

| 难点 | 级别 | 项目做法 | 残余问题 |
|---|---|---|---|
| PII 与偏差 | P0 | 入模前遮蔽 | 地区、学校、经历时间仍可能成为代理变量 |
| 经历边界 | P1 | LLM life-event 切分 | 必须用 JSON Schema、日期校验和原文跨度 |
| 候选聚合 | P1 | top-2 加权 | 应与必备技能、年限、最近性和职业连续性结合 |
| 精排成本 | P2 | top-5 后 LLM 比较 | 候选多时用 tournament 或 listwise rerank |
| 可解释性 | P1 | 返回命中经历 | 还需区分“简历声明”与“系统推断” |

## 对 SmileBoss 的使用建议

- 直接借鉴：PII 最小化、经历原子化、候选级聚合、召回与精排分层。
- 改造：权重不要固定为 top-2；按岗位配置 `max(event_score) + coverage + required_skill + recency + duration`，并通过离线标注集校准。
- 面试联动：推荐时未被证实的关键技能直接生成 `evidence_gap`，AI 面试规划器据此选题和追问。
- 不建议：用学校、年龄、性别、婚育等字段参与相似度；把 LLM 排名直接作为淘汰依据；保存不必要的原始 PII 到向量库。
