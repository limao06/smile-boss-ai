# 13. DeepSearcher：Collection Router、子查询、YES/NO 重排与反思

## 项目卡片

- GitHub：[zilliztech/deep-searcher](https://github.com/zilliztech/deep-searcher)
- 本地源码：`research/source-code/rag/13-deep-searcher`
- 锁定版本：`d89e37cdfbbe`
- 定位：面向私有数据的深度检索 Agent，包含 Naive/Deep/ChainOfRAG 等路径。
- 一句话判断：它把深度检索拆成“选集合—拆子问题—宽召回—判相关—反思缺口—父文本扩展”，非常适合候选人深度报告而非实时推荐首屏。
- 重要性：P1/P2。

## STAR

### S — Situation

企业知识分散在多个 collection，复杂问题包含多个子意图；一开始选错库或只检索一次，后续生成无法补救。仅按向量分排序也常把“主题相近但不能回答”的块排在前面。

### T — Task

先路由到正确集合，将问题拆成有限子查询并并行检索，用 LLM 做相关性判断；若证据不足，再生成针对缺口的新查询，同时回填更宽的父文本。

### A — Action

Collection Router 选择相关知识集合；查询最多拆为约 4 个子查询，分别向量检索。候选块由 LLM 用 YES/NO 判定是否真正回答子问题。系统反思缺失信息，可进行最多约 3 轮 gap queries；`wider_text` 机制回填父块。不同复杂度由 Naive、Deep、ChainOfRAG 等实现选择。

### R — Result

对多跳和多资料问题的证据覆盖更好，也把相关性从纯相似度提升为“是否可用于回答”。缺点是大量 LLM 判定带来延迟，YES/NO 缺少细粒度分数，router 误判可能使正确 collection 根本没被搜索。

## 完整执行流

1. 输入问题和用户权限上下文。
2. Router 选择一个或多个 collection。
3. Planner 生成最多 4 个互补子查询。
4. 并行向量搜索，收集块和来源。
5. LLM 对每个“子问题—块”判断 YES/NO，删除不可回答片段。
6. 父块扩展补充上下文，去重并控制 token。
7. 反思证据缺口；若需要且未超 3 轮，生成 gap query 回到检索。
8. 汇总事实、冲突和引用，生成最终答案。

## 难点

| 难点 | 级别 | 项目做法 | 改进 |
|---|---|---|---|
| 集合路由 | P1/P0 | LLM router | 权限必须在路由前固定，低置信度搜索多个授权库 |
| 子问题覆盖 | P1 | 最多 4 个 | 招聘用技能/年限/成果/约束模板增强 |
| 相关性精排 | P1 | YES/NO | 输出 relevance、answerability、novelty 三维分数 |
| 循环成本 | P2 | 最多 3 轮 | 无新增证据、预算或超时即终止 |
| 父块扩展 | P1 | wider_text | 限制每来源父块数量，避免上下文爆炸 |

## SmileBoss 借鉴

候选人深度报告可以路由到简历、面试记录、授权作品集、职位知识和招聘流程数据；每个库都必须先做 ACL。把 YES/NO 重排改成结构化证据判定：“是否直接支持某能力、证据强度、时间、主体、是否自述”。实时推荐只运行一次召回+重排，深度分析才允许反思循环。
