# 08. STORM：多视角检索、模拟访谈、提纲与长文写作

## 项目卡片

- GitHub：[stanford-oval/storm](https://github.com/stanford-oval/storm)
- 本地源码：`research/source-code/agent-text2sql/08-storm`
- 锁定版本：`fb951af7744d`
- 定位：有引用的长篇研究报告生成；Co-STORM 增加专家、主持人、人类与动态 mind map。
- 一句话判断：这是 Agent 协作写作中最值得细读的项目之一，因为它先做“知识策展和提纲”，再写文章，而不是让模型从搜索结果直接拼长文。
- 重要性：P1。

## STAR

### S — Situation

长文写作最常见的问题是视角单一、结构先天不足、章节重复和引用漂移。单 Agent 边搜边写会过早锁定叙事，后来发现的新信息无法自然进入结构。

### T — Task

先发现多个写作视角，模拟作者向专家追问并收集带来源笔记；基于知识形成提纲，再分节写作、统一引用和润色。Co-STORM 还允许主持人组织多专家和人类共同探索。

### A — Action

STORM 先从主题产生多种 persona/perspectives，每个“作者”与“专家”进行多轮问答；专家搜索网页并用证据回答，形成信息表。系统汇总知识后生成 outline，再按 section 检索相关笔记写正文，最后拼接、补引和润色。Co-STORM 使用 turn policy 决定下一专家/主持人动作，并动态更新 mind map，让人类可介入讨论。

### R — Result

报告覆盖面和结构显著优于一次性写作，引用能绑定研究笔记。代价是搜索/对话次数多、来源质量参差、不同章节仍可能冲突；模拟 persona 只是覆盖视角工具，不能被视为真实专家意见。

## 完整执行流程（写作流）

1. 将用户主题转为 research brief 和边界。
2. 生成互补视角/persona，去重并限定数量。
3. 每个作者 Agent 提问；专家 Agent 搜索并基于来源回答。
4. 保存 `claim -> source -> quote/span -> confidence` 的研究笔记。
5. 合并笔记，构建 outline/mind map。
6. 为每节选择相关笔记，分节并行起草。
7. 事实核查引用、跨章节冲突和覆盖缺口。
8. 总编辑统一结构、术语、重复和语气；不新增未引用事实。
9. 输出报告、引用和未解决问题。

## 难点

| 难点 | 级别 | STORM 做法 | SmileBoss 应用 |
|---|---|---|---|
| 视角覆盖 | P1 | persona-guided research | 候选报告按技能、成果、风险、动机、证据缺口视角 |
| 先研究后写 | P1 | notes -> outline -> sections | 禁止写作者直接访问未筛选原始材料 |
| 引用漂移 | P1 | 信息表/来源 | 每条结论绑定 evidence ID，润色后再校验 |
| 跨节一致性 | P1 | 最终整合 | 共享术语表和事实 ledger |
| 外网可信度 | P1/P0 | search | 招聘人物信息不得无授权扩搜和推断 |

## SmileBoss 借鉴

候选人综合报告采用 STORM 式流程：先按岗位能力建立研究视角，再从简历和面试证据形成 notes，随后提纲和分节写作。报告中明确区分“候选人陈述、面试观察、系统推断、缺失证据”。不使用公开网络搜集候选人隐私或负面背景。
